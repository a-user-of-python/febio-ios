# FEBio iOS — Phase 1 spike

**Question:** can the FEBio finite-element solver run *natively,
in-process* on an M-series iPad?

**Spike answer being tested:** a minimal iPad app ("FEBio Spike")
that cross-compiles the FEBio solver core for iOS arm64, links it
into the app, and — on one tap — solves a bundled reference model
through FEBioLib (the same in-process library API FEBio Studio
uses), then displays the headline results in large text.

This follows the prove-the-engine-first pattern: no port of the
FEBio Studio UI is attempted until the solver itself is proven
on-device.

## Reference model

`Model/tension-block.feb` — a 10 × 2 × 2 mm neo-Hookean block
(E = 10, ν = 0.3), 40 hex8 elements / 99 nodes, left face fixed,
right face prescribed +1.0 mm in x (10% uniaxial tension, one static
step, 10 increments). Generated by `Scripts/gen_model.py`.

Host reference numbers (Linux, FEBio built from the pinned commit
below, Skyline solver): see `REFERENCE.md`. The on-device run must
reproduce them (max displacement is prescribed, so it must read
exactly 1.0000 mm).

## Layout

- `App/` — SwiftUI spike app + `febio_facade.{h,cpp}`, a thin
  extern-C facade over FEBioLib. Swift drives, C++ computes; the
  facade only forwards (init library → load .feb → solve → read
  back maxima). Results are read from the solved model: nodal
  displacements from node positions, von Mises from the elastic
  material points at each solid element's Gauss points.
- `Model/` — the bundled reference model.
- `HostHarness/` — a host (Linux/macOS) driver that runs the exact
  facade code path against a desktop FEBio build; produces the
  reference numbers.
- `Scripts/` — `gen_model.py`, `gen_project.py` (deterministic
  Xcode project generator), `build-febio-ios.sh` (clone + patch +
  cross-compile FEBio), `ios.toolchain.cmake`.
- `Patches/` — every patch applied to FEBio's build, enumerated.
  FEBio is MIT-licensed, so patching is permitted; nothing is
  patched silently.
- `App/omp_stub.c` + `Scripts/ios-shim/omp.h` — app/build-side
  additions (not FEBio patches): FEBio calls a few OpenMP API
  functions explicitly (and one file includes `<omp.h>`), while the
  iOS SDK has neither the header nor the runtime. The shim header
  declares the API and the app supplies single-threaded stubs.
  Consequence: the spike solves on one thread.

## FEBio version

Pinned to FEBio commit `9605327359ded64ea0d65dd1aeca484fc45a9acd`
(FEBio 4.13.0 development tree, 2026-10-27), fetched by CI as a
codeload archive from https://github.com/febiosoftware/FEBio.
Built with **MKL off** — the bundled
Skyline solver is used instead of Intel MKL/Pardiso, so the build is
pure ARM with no Intel dependency.

## Building

GitHub Actions (free, standard `macos-26` runner): the workflow
cross-compiles FEBio for iOS arm64, builds the app unsigned, and
uploads `FEBioSpike-unsigned.ipa` as a build artifact.

## FEBio Studio port (phase 2)

The spike proved the solver on-device. The follow-on work in
`Studio/` ports the **actual FEBio Studio 3.2.0 application**
(Qt Widgets UI, QRhi viewport) to iOS, with touch added — no
replacement UI. Start with `Studio/INVENTORY.md` (build/module
inventory, the subprocess audit, the rendering analysis, and the
patch list). The `build-studio.yml` workflow produces
`FEBioStudio-unsigned.ipa`. FEBio Studio is MIT-licensed, like
FEBio; the Studio license text is in the upstream source.
